Brief Introduction to Networks

  • A Communications Model: Data Communication deals with the transmission of signals in a reliable and efficient manner

    • Source: generates data to be transmitted
    • Transmitter: Converts data into transmittable signals
    • Transmission System: Carries data
    • Receiver: Converts received signal into data
    • Destination: Takes incoming data

  • Networking: technology and architectures of the communication networks used to interconnect communication devices

    • Point to point communication is not usually practical

      • Devices are too far apart
      • Large set of devices would need impractical number of connections

    • Solution is a communications network

  • Classification of Comms. Networks:

    • 第一维度：网络分类（按规模 / 范围）：

      network size, complexity, the distance it covers and its physical architecture

      Network Type Full Name Geographic Scope Key Features Transmission Media / Technology Example
      PAN Personal Area Network Short range Low power; Low-cost small networks; Part of IoT ecosystem Low power for transmission Bluetooth, Zigbee, USB
      LAN Local Area Network Limited area (classroom, building, office) Privately owned; Allows resources to be shared Traditionally 4–16 Mbps, now 100Mbps–Gigabit A few computers connected to a printer

    • 第二维度：物理连接方式（Line Configuration + Topology）

      • Line Configuration = connections: the way two or more communication devices attach to a link

      • A link is a physical communication pathway that transfers data from one device to another.

      • Point-to-Point line configuration provides dedicated link between two devices. Uses the entire capacity of the channel e.g. TV remote using infrared.

      • Point-to-Multipoint line configuration is one in which more than two specific devices share a single link. The capacity of the link is shared.

      • Topology: the way a network is laid out, physically or logically. Two or more links form a topology

        Topology of a network is the geometric representation of the relationship of all the links and linking devices (called nodes) to each other

        Topology Key Characteristics & Connections Advantages / Strengths Disadvantages / Weaknesses
        MESH Every device has a dedicated point-to-point link to every other device. Eliminate traffic problem; Robust and guarantees privacy; Easy fault identification. —
        STAR Each device has a dedicated point-to-point link only to a central controller called hub. Less expensive; Needs only one I/O port to connect to hub; One link disconnect doesn’t affect others. If the hub fails, all connections are affected, and the entire network goes down.
        TREE A variation of star; Most devices connect to a secondary hub, which in turn connects to central hub. — —
        BUS Nodes connected to a bus cable by drop lines and taps; Multipoint line configuration. Very old technique Limits the number of taps and distance; A fault in the cable will stop all transmission.
        RING Dedicated point-to-point line only with two devices on either side; Signal passed in one direction. Easy to design. Ring length limits max devices; Adding/removing requires changing two connections; Any break disables entire network.
        HYBRID Combine several topologies as subnetworks linked together in a larger topology. Can connect different departments (e.g., ring, bus, star) through a central hub. —

    • 第三维度：数据传输方向（Transmission Mode）: The mechanism of transferring data between two devices connected over a network.→direction of signal flow between two linked devices.

      • Simplex is unidirectional i.e. signal flows only in one direction
      • Half-Duplex is where each station can both transmit and receive, but one at a time
      • Full-Duplex is where both stations can transmit and receive simultaneously

    • 第四维度：核心交换技术（Alternative Technologies）Circuit switching and Packet switching

      Feature Circuit Switching Packet Switching
      Setup Requirement Must be set up before nodes can communicate. Not explicitly required/stated as pre-set.
      Communication Path Dedicated communication paths established for the duration of the conversation. Packets passed from node to node between source and destination.
      Data Transmission Continuous / Stream based. Data sent out of sequence; Small chunks (packets) of data at a time.
      Switch Function Switch can only make it active or inactive. Implicitly involves routing/forwarding packets.
      Efficiency Less efficient. More efficient compared to circuit switching network.
      Common Use / Example Telephone network. Terminal to computer and computer to computer communications.

  • What is a bit?

    • A bit (short for binary digit) is the smallest unit of data in a computer. A bit has a single binary value, either 0 or 1.

    • All data can be represented up to arbitrary precision by bits

  • What is Bandwidth?

    • Definition: The range between the lowest and highest frequencies used for a particular application.

    • Relationship to Data: The more bandwidth a data connection has, the more data it can send and receive at one time.

    • Unit of Measure: Hertz (Hz).

      Question: Is all the signal power concentrated only within these frequencies?

      Answer: Not necessarily, but there are strict rules for defining the effective range.

    • 关注质量：The 3 dB Rule: A common engineering standard used to define the boundaries of the bandwidth.

    • 严格要求：Spectral Regulation Agencies: These agencies take a stricter view to prevent interference.

      • The 99% Rule: 99% of the signal power should be contained within the defined bandwidth.
      Feature Analog Bandwidth Digital Bandwidth
      Unit Hertz (Hz) Bits per second (bps)
      Context Frequency range of the signal. Data transmission rate/capacity.

  • Network Performance

    • Transmission is subject to errors: delayed, lost, mis-ordered, duplicated

    • QoS (Quality of Service): to give some kind of assurance to an application

      • High data rate: video, graphics and quality audio
      • Interactive services： 200ms round trip time (RTT往返时间)，low jitter(低抖动) for conversational services

    • Delays: Processing, Packetisation, Queuing, Transmission (data rate), Propagation

  • Reliable Transmission – ARQ and Flow Control Protocols：可靠=正确，不丢失，顺序

    • Protocol messages – PDUs: 发送请求与接收指示 DATA.req/DATA.ind + PCI: 报头 header, checksum (CRC/校验和)

    • Automatic Repeat Request (ARQ): 解决可靠性 (Reliability)

    • Stop-and-wait (Idle-Request) 发一个等一个

      • 成功的传输 (Successful Transmission)

        这是图左半部分展示的内容：

        • DATA.req: 发送端（Tx）的上位机请求发送数据。

        • DATA 发送: Tx 向接收端（Rx）发出一个数据包。

        • CRC ok: Rx 收到后进行循环冗余校验，发现数据完整无误。

        • DATA.ind: Rx 将收到的数据交付给上位机。

        • ACK 与 DATA.conf: * Rx 发回一个 Acknowledgement (确认字符)。

          Tx 收到 ACK 后，触发 DATA.conf，确认之前的发送任务已成功完成。

      • 出错与重传 (Error and Re-transmission)

        这是图右半部分展示的核心，也是 ARQ 机制存在的意义：

        1. 发送与损坏 (Bad CRC): * Tx 再次发送一个数据包。但在传输过程中由于干扰，Rx 收到后校验失败（图中打叉的红色位置：bad CRC）。

        2. Rx 的处理: 当数据校验失败时，Rx 会直接丢弃这个包，并且不发送 ACK。

        3. Tx 的等待与超时 (Timeout):

        • Tx 在发送数据的同时，开启了一个计时器（图中上方的花括号：timeout）。

        • RTT(Round Trip Time)往返时长，timeout参考

        • 由于 Rx 没有发回确认，Tx 的计时器到时了。

        1. 重传 (Re-transmit):

        • 一旦发生 timeout，Tx 意识到对方可能没收到（或收到了坏包）。

        • Tx 自动重新发送同一个数据包。

        1. 最终成功: * 这一次 Rx 校验通过（打勾处），发回 ACK。
        • 数据最终成功交付（DATA.ind）

​ 数据包和ACK都需要带SN序列号！

  1. For DATA Packets (数据包带序列号)

  • Prevent Duplicates (防止重复): If an ACK is lost, the Tx will retransmit the DATA. Without an SN, the Rx cannot distinguish between a retransmission and new data. (如果确认信号丢了，发送端会重传。没有序列号，接收端分不清是“重传包”还是“新包”。)

  • Discard Strategy (丢弃策略): The Rx uses the SN to identify if it has already processed this packet. If the SN matches the previous one, the Rx discards the duplicate but resends the ACK. *(接收端靠序列号识别是否处理过该包。如果编号重复，则丢弃该包，但必须重发确认信号以告知发送端停止等待。)*

    1. For ACK Frames (确认帧带序列号)

  • Avoid Ambiguity (消除歧义): In networks with high delay, an old ACK might arrive late. The SN tells the Tx exactly which DATA packet is being acknowledged. (在高延迟网络中，旧的确认信号可能迟到。序列号告诉发送端：现在这个确认到底对应哪一个数据包。编号不对应不停止计时)

  • Prevent Misinterpretation (防止误判): Without SNs, the Tx might receive a delayed ACK for a previous packet and mistakenly think the current packet was delivered successfully. (如果没有序列号，发送端可能会把“迟到的旧确认”误认为是“对当前新包的确认”，导致逻辑混乱。)

    1. Efficiency Note (效率备注)

  • 1-bit Sequence Number (1位序列号): For the Stop-and-Wait protocol, a single bit (0 or 1) is sufficient because only one packet is “in flight” at any time. (对于“停止-等待”协议，1位序列号（0和1交替）就足够了，因为链路上任何时刻只有一个包在传输。)

  • Continuous- Request:

  • 核心机制：窗口 (Window)

    • Tx视角： Window size，允许 Tx 在未收到 ACK 前连续发送多个 PDU（x PDU “credits”）。
    • **Rx 视角：**Rx may also have notion of window: must know which SNs to expect

    p1管接收，p3管发送

    • 优势： works well for reliable underlying service

  • Re-transmission strategies：Trade-off: network traffic vs. buffer space + complexity

    1. Go-back-N (GBN)：发现错误，退回到错误处重发之后的所有包,

      • Core Logic: If PDU lost, Rx will wait for retransmission and ignore all additional PDUs (丢包后，后续收到的包全扔掉)。
      • Math Requirement: m > w (SN modulus > Window size)。
      • Drawback: Unnecessary Retransmissions. (即便 Rx 有缓存和重排能力，GBN 依然会重传后续所有包，造成浪费)。

      ws=4

    2. Pure Selective Re-transmission (Pure SR)：只重传出错的那一个包

      • Mechanism: Rx ACKs each packet individually. (每个包独立确认)
      • Handling Loss: If PDU lost/corrupted, Rx will ACK additional PDUs, ait for re-transmission (收到后续的包照样回确认).
      • Tx View: Tx sees a “hole” in ACKs. (Tx 发现确认号里缺了一个，意识到该包丢失)
      • Buffering: Rx waits for missing PDU before delivering data to user. (缓存后续包，补齐“洞”后再交货)

      有buffer直接移4格

    3. Selective Re-transmission Variation (SR 变体)

      • Mechanism: Rx uses cumulative ACKs. (累积确认)，断后收到不发ACK，“5”具有包含性
      • Handling Loss: If PDU lost at Rx, no additional ACKs are sent. (丢包后不再发后续确认，直到补发成功)
      • Tx Strategy: Tx uses go-back-N strategy. (Tx 超时后按 GBN 逻辑重发)
      • Math Requirement: m > 2w - 1

      • Heavily Delayed PDU Problem (严重延迟包问题)
      • Problem: Old PDU arrives in new window. (旧包走得太慢，掉进了新一轮序列号循环中，Rx 会误以为是新包)
      • Solutions:
        1. Use large window size (本质是配合足够大的m)。
        2. Network discards old PDUs: 使用 “time limit” in PDU (数据包自带生存时间，过时由网络自动销毁)。

  • 具体实践中 Full Duplex Service: piggybacked

  • 理想机制：ACKs can be piggybacked on DATA:→ separate SN fields for data and ACK in header

  • 现实约束: 流量非对称Relies on two-way data flow, 所以 many “pure” ACKs still possible (e.g. WWW access)

  • 工业方案: delayed ACK (e.g. TCP)延迟确认等ACK上车，但时间不会太长

  • 衍生挑战: large data frames delay ACKs拖慢时间误以为超时: timeouts

  • flow control: Limited resources at end-systems 解决拥塞/淹没

    • Stop / Go (基于阈值的控制)：Rx controls Tx PDU rate

      HWM (High Water Mark): 高水位线（高阈值）。当 Rx 的缓存占用达到这个点时，Rx 发送 RNR (Receiver Not Ready)，叫 Tx 赶紧停车。

      LWM (Low Water Mark): 低水位线（低阈值）。当 Rx 处理完数据，缓存空闲到这个点时，Rx 发送 RR (Receiver Ready)，叫 Tx 继续发货。

      Safety: HWM 通常设置得比物理极限低一点（Set low for safety），防止 RNR 消息在路上丢失导致 Rx 直接溢出（Overrun）

    • Sliding Window

    • Mechanism: Rx tells Tx exactly how much data to send via the Window field in ACKs.Rx 通过 ACK 动态告诉 Tx 还能发多少，ACKs carry A (last SN received) and W (current available buffer space). Tx can send (W - u) packets– u is the number of packets outstanding

    • Flexibility: Rx can dynamicly vary window size; W=1 equals stop-and-wait, ther window sizes allow selective re-transmit

    • Commonly used in the Transport Layer (e.g., TCP)

  • Protocol

    • Protocol Definition: A set of rules followed by the sender, receiver, and intermediate devices for effective communication. (通信各方必须遵守的共同规则)

    • Protocol Layering: Dividing complex communication tasks into manageable layers, where each layer has its own protocol. (将复杂任务分层处理，降低复杂度)

    two principles：1. Each layer should be able to perform two opposite tasks, one in each direction. 2. The two objects under each layer at both sides (sender and receiver) should be identical.

    • Key Architectures:
      • OSI Reference Model: A theoretical framework that was not fully adopted in practice. (理论完美的七层模型，但应用较少)
      • TCP/IP Suite: The de facto industry standard and the most widely used architecture today. (事实上的工业标准，互联网的核心)

  • OSI Reference Model

    • Definition: An ISO standard framework covers all aspects of network communication, consisting of seven separate but related layers. (ISO 制定的七层网络通信框架)

    Framework vs. Protocol: OSI is a theoretical model; protocols implement the functions defined within these layers. (OSI 是模型/框架而非具体协议)

    • ISO：Developed by the International Organization for Standardization, a multinational body dedicated to worldwide agreement on international standards.

    • Core Goal: To enable communication between any two systems regardless of their underlying architecture. (跨平台、跨架构的开放式通信)

    • Design Principles (Layering-structuring technique):

      • Each layer performs a related subset of the functions required to communicate with another system.
      • Vertical Service: Each layer provides services to the upper layer and utilizes services from the lower layer. (上层使用下层服务)
      • Modularity: Changes in one layer do not affect others, ensuring system flexibility. (层间独立，互不影响)

    • Status: A theoretical success but a practical failure because it was delivered too late; TCP/IP is the actual industry standard (de facto). (理论巅峰，实际被 TCP/IP 取代)

    • 七层细则

      L7. Application (应用层)

      • 给谁用：Enables users to access the network: 终端用户接口。
      • 做什么：Means for applications to access OSI environment.
      • 特点：Everything at this layer is application-specific (针对特定应用).

      L6. Presentation (表示层)

      • 做什么：Data formats and coding: 负责数据格式与编码。
      • 功能：编码转换interoperability between different encoding methods；Encryption/Decryption & Data compression (加密解密与压缩).

      L5. Session (会话层)

      • 做什么：dialog control
      • 功能： Establishes, manages and terminates connections between applications (建立/管理/终止连接)；synchronization；Recovery (恢复机制).

      L4. Transport (传输层)

      • 做什么：end-to-end data delivery (端到端交付)
      • 特点：reliable→Error free transmission, no losses, delivers data in sequence (无错、无丢包、按序交付).
      • 代表：TCP
      • 不可靠：User Datagram Protocol (UDP).

      L3. Network (网络层)

      • 做什么：Responsible for the source-to-destination delivery of a packet (源到目的地交付).
      • 功能：Assigns sender’s and receiver’s IP address to form a packet；Routes the packets and determines the path of data (路由与寻址).

      L2. Data Link (数据链路层)

      • 做什么：Provides hop-to-hop delivery in a closed network (跳到跳交付).
      • 功能：activating, maintaining and deactivating communication links；Frames data packets and prepares for transmission (成帧)；Detects and corrects transmission errors (检错与纠错).

      L1. Physical (物理层)

      • 做什么：Physical interface between devices (物理接口标准).
      • 功能：Defines physical means of sending/receiving data on a carrier；Converts binary sequence into electrical or electromagnetic signal (二进制转信号).and sends them over transmission medium (cable or air)

    • TCP/IP Protocol Architecture：

    1. 核心背景与定义：Transmission Control Protocol/ Internet Protocol

      • 用处：a suite of communication protocols used to interconnect network devices on the internet
      • Origin: 由美国国防部US Defense Advanced Research Project Agency DARPA 开发。
      • TCP Function→control: defines how applications can create channels of communication across a network在网络中创建通信通道. It also manages how a message is assembled into smaller packets分装成小包 before transmitting over the internet and reassembled in the right order按序重组 at the destination address
      • IP Function: 定义如何 address and route（编址与路由）each packet to make sure it reaches the right destination
      • model例子
      • Application layer – Host to host or transport layer – Internet layer – Network interface layer – Physical layer
      • Sometimes, Physical layer is included in the Network Interface layer, combining Data link and Physical layers from the OSI model

    2. 五层模型职能 (Layer Functions)

      Application Layer (应用层)

      • Function: Responsible for providing the channel for interaction between applications and end users. (提供应用与用户的交互通道)
      • Integration: Combines OSI’s Session, Presentation, and Application layers.
      • Examples: HTTP, SMTP, FTP, SSH, DNS. (这些协议通常关联特定的 associated with one or more Port number 端口号)

      Transport Layer (传输层 / Host to host)

      • Function: Responsible for maintaining end-to-end communications; arranges packets in sequence.(维护端到端通信并排序)→Reliable delivery of data
      • Protocols: Includes TCP (Reliable) and UDP.

      Internet Layer (网络层)

      • Function: 发Creating the packets; 收Accepts and delivers packets:identifying source and destination using IP addresses. (创建包并识别 IP 源/目地址)
      • Routing: Performs routing functions across multiple networks. (执行跨网路由)

      Network Interface Layer (网络接口层)

      • Function: Exchange of data between end system and network. (端系统与网络间的数据交换)
      • Mechanism: Adds MAC address and creates a frame. (添加 MAC 地址并成帧)
      • Provides services like priority.

      Physical Layer (物理层)

      • Function: Physical interface between device and medium. (设备与媒介的物理接口)
      • 定义Characteristics of transmission medium
      • Focus: Defines signal levels and data rates. (定义信号电平和数据速率)

      1. 分层原则 (Layering Principles)

        • Adjacent Communication: Each layer only communicates with adjacent layers. (只与相邻层通信)→Software only needs to know the Transport layer, not how bits are encoded in the Physical layer. (上层无需关心底层物理实现)
        • Control Information: Each layer adds its own control information (Headers) to do its job. (每一层通过添加控制信息来执行功能)
        • Peer-to-Peer: Peer layers on different hosts use the control information to understand each other. (对等层之间利用控制信息进行对话)

TRANSPORT LAYER

  1. TCP: The Reliable Foundation (可靠基石)

    Connection Oriented Communication: Devices establish a connection before data exchange. (通信前先建连)→a requirement for an acknowledgment

    Reliable Connection: Ensures data integrity via acknowledgments; retransmits missed or corrupted data. (通过确认号保证数据一致性，错漏重传)

    优点：Segmentation and In-Sequence + Error and Flow Control

    Weakness: Slower speed and higher overhead due to control mechanisms. (开销大，速度相对慢)

  2. Protocol Mux / Demux (多路复用/解复用)

  • Layer Identification:

    |Identifier (标识符)|Layer (所在层)|Destination (投递目标)| |-|-|-| |Ethertype|Data Link (Ethernet)|Network Layer (IP/ICMP)| |Protocol identification|Network (IP)|Transport Layer (TCP/UDP)| |Port Number|Transport (TCP/UDP)|Specific Application|

    process-to-process communication is through the client-server paradigm

  • 端到端：A application process on the local host (client) needs services from a process usually on the remote host (server). Local and remote hosts are defined by IP addresses.

  • 进程：Port Numbers: Used to define application processes on a host.

    • 机构：ICANN (International Corporation for Assigned Names and Numbers)
    • Well-known ports (0-1023): Assigned and controlled by ICANN (e.g., HTTP=80, FTP=21). Services are usually identified through “well-known” Ports
    • Registered ports（1024-49151）: not assigned and controlled by ICANN, but can be registered with ICANN to prevent duplication
    • Dynamic or private ports (49152-65535): Ephemeral ports chosen at random by clients.

  • 合体成为Socket Addresses:

    • Definition: A unique entity identified by A combination of IP address and port number, allow for unambiguous peer-to-peer communication throughout the Internet→identifies a unique process

    • Requirement: A pair of socket addresses (client socket + server socket) is required to make a connection.

  1. TCP Features：“features of TCP”

  2. Connection Establishment: The Virtual Path

    • Connection-Oriented: TCP establishes a virtual path between source and destination using a 3-way hand-shake. (通过三次握手建立虚拟路径)
    • Purpose: This sequences S/N (Sequence Numbers) in both directions to ensure everything that follows is tracked. (初始化双向序列号)
    • Context: All segments belonging to a message are sent over this virtual path. (同一消息的所有段都沿这条虚拟路径传输)

  3. Data Processing: From Stream to Segment (buffer+从流到段)

    • 通信模式：full-duplex buffered
    • 如何处理流：Byte-stream Oriented: TCP treats data as a continuous stream of bytes. It uses sender and receiver buffers to manage the disparity between the speed of producing and consuming. (利用缓冲区平衡生产与消费的速度差异)

    • 具体处理方式（接收为例）：TCP on the destination host then empties the contents of the packet into a receive buffer, and the receiving process reads from this buffer at its leisure.
    • 功能→从流到段：Segmentation: TCP buffers enough bytes to fill a Segment, adds a control header, and encapsulates it in an IP datagram. (将字节流打包成 Segment 并封装进 IP 包)

  4. In-Transit Management: The “Guardians” (四大护法+方法) reliablity

    • Ordering (The Organizer): Segments delivered in order by using sequence numbers. (利用序列号保证按序到达)
    • Error Control (The Inspector): Uses Error Detection (Checksum) and Retransmission to resend corrupted or lost packets based on positive acknowledgement. (通过校验和与确认重传修复丢失/损坏的数据)
    • Flow Control (The Gatekeeper): Prevents the sender from overrunning the capacity of the receiver(保护接收端：防止塞爆对方缓冲区)
    • Congestion Control (The Traffic Cop): Adaptive algorithms to prevent the sender from overloading the network. (保护网络：根据路况自适应调整)
    • 方法：A *sliding window mechanism* for both reliability through positive acknowledgement retransmission and flow control to prevent receive buffer overrun and to offset transitory network congestion.

  5. Specialized Handling (特殊处理)

    Flags: I.e., to enable the rapid PUSHing of urgent data. (利用标志位如 PUSH 处理紧急任务)

  6. Header

    32bits一行，4bytes，20B必须

  7. Identification: Port Numbers (16 bits each)

    Function: Defines the port number of the application program in the server/client. (定义服务器/客户端中应用程序的端口号)

    Socket: The combination of IP + Port. (IP 与端口的结合)

  8. The Numbering System: Seq & Ack (32 bits each)

    Byte-oriented Numbering: TCP numbers each byte of data. The numbering starts with a random Initial Sequence Number (ISN) which is usually different in each direction (TCP 为每个字节编号，起始号 ISN 是随机的)

    • Sequence Number: Defines the number assigned to the first data byte contained in that segment. (该段中第一个字节的编号)
    • Acknowledgment Number:
    • Cumulative ACK: Defines the number of the next byte a party expects to receive. (累积确认：表示期待接收的下一个字节) If a receiver gets segment x, it returns x+1 as the ACK. 核心：按顺序来，缺啥要啥
    • Piggybacking: Acknowledgment and data can be sent together in one segment. (确认号可以和数据“捎带”在一起发送)

  9. Flow Control: Window Size (16 bits)

    Definition: Defines the max bytes (up to 65,535) the receiver can handle. (定义接收方能处理的最大字节数)

    Dictation: This value is the receiving window (rwnd). The sender must obey the dictation of the receiver. (发送方必须服从接收方的指令)

  10. Control Flags (6 bits): The “Switches” (控制开关)

    • 作用：enable flow control, connection establishment and termination, connection abortion, and the mode of data transfer in TCP

    URG: Signifies segment contains urgent data. (紧急数据)

    ACK: Set any time the Acknowledgment field is valid. (表示 ACK 字段有效)

    PSH (Push): Notify receiving TCP that data must be delivered as soon as possible without waiting for more data. (催促立即交付，不要等缓冲区满)

    RST (Reset): Used to abort the connection if the receiver becomes confused. (连接重置/中止)

    SYN & FIN: Used for establishing and terminating a connection. (同步/终止：用于建立和断开连接)

  • Reliability Overview: Positive Acks (可靠性保障)

    Sliding Window: Governs the number of segments that can be in-transit. (控制在途报文的数量) the“width”of the window is set by the effective window parameter

    顺利：the destination returns an acknowledgement to the originator containing an acknowledgement number set to the sequence number of the last contiguous byte received plus one

    Or Duplicate Acks: If segments are received out of sequence, the ACK number stays the same until the gap is filled. (如果乱序到达，ACK 号保持不变，直到缺口补齐，从而产生重复确认)

  • data offset：payload头在哪，padding补齐

  1. TCP Connection Behaviour

  • States & Handshake (状态与握手): Client does active open; Server does passive open (LISTEN). Uses SYN, SYN+ACK, ACK to reach ESTABLISHED. (客户端主动打开，服务器被动监听。通过三次握手建立连接。)

    1. 连接建立（三次握手）

    Client（主动打开 Active open）：

    • CLOSED → SYN-SENT：发送 SYN 报文，发起连接请求

    Server（被动打开 Passive open）：

    • CLOSED → LISTEN：等待连接请求

    握手流程：

    1. Client → Server：SYN（同步序列号）
    2. Server → Client：SYN+ACK（同步自己的序列号 + 确认客户端）
    3. Client → Server：ACK（确认服务器）

    双方进入 ESTABLISHED 状态，开始数据传输

    1. 数据传输阶段

    双方都处于 ESTABLISHED，可以双向收发数据

    遵循右侧的序列号 + 确认号规则

    1. 连接释放（四次挥手）

    Client（主动关闭 Active close）：

    • ESTABLISHED → FIN-WAIT-1：发送 FIN 报文，表示 “我没数据要发了”

    挥手流程：

    1. Client → Server：FIN
    2. Server → Client：ACK（确认收到 FIN）
    3. Server 处理完队列数据后 → Client：FIN（服务器也没数据要发了）
    4. Client → Server：ACK（确认服务器的 FIN）

    客户端进入 TIME-WAIT，等待 2MSL（最长报文段寿命）后回到 CLOSED

    服务器收到最后一个 ACK 后直接回到 CLOSED

  • SN: All data contains a sequence number for ordering. (所有数据都有序列号，用于排序和确认。)

  • Acks (确认): Sent in response to received data; they are cumulative (value = first missing byte). (确认号是累积的，其值表示接收方期望收到的下一个字节。)

  • Retransmission (重传): A dynamically adjusted timer (based on RTT) resends data if no ACK received. (基于动态RTT估算的重传定时器，超时未收到ACK则重发数据。)

  • Duplicate Acks (重复确认): Receiving three or more triggers fast retransmit (differs by implementation). (收到三个或以上重复ACK会触发快速重传，具体行为因实现而异。)

  • TCP Sliding Window–flow control

  • Window Structure (窗口结构): The sliding window contains: sent & acked, sent & not acked, can be sent directly, can’t send yet. (发送方窗口分为：已确认、已发送未确认、可发送、暂不可发送。)

  • Effective Window (有效窗口): The effective window size is ALWAYS set to the MIN of the congestion window and advertised window. (有效窗口大小始终取拥塞窗口和接收方通告窗口的最小值。)

    • 网络→Congestion Window (拥塞窗口 - cwnd): Regulated by timely ACKs; prevents overwhelming the network. “Slow-start” is aggressive (exponential growth). (由ACK反馈调节，防止网络拥塞。慢启动过程实际很激进，呈指数增长。)
    • 接收端→Advertised Window (通告窗口 - rwnd): Set by the receiver; indicates available buffer space. Provides flow control. (由接收端设置，反映其可用缓冲区大小，实现流量控制。)

  • Silly Window Syndrome

    • four windows for a bidirectional communication with piggybacking 在带捎带确认的双向（全双工）通信中，一共有四个窗口。
    • SWS定义：during large data transfers whereby the receiving host fails to open its window wide enough (for example, due to lack of resources) for the sending host to send data in large segments
    • 原因：receiver 处理慢，transmiter 产生慢
    • 发送方：In accordance with the Nagle algorithm a host avoids aggravating SWS by only sending a segment under the following conditions:
    • A maximum-sized segment can be sent(能凑满一个最大尺寸段时才发送)
    • All outstanding segments have been acked before small segments transmitted(所有已发送未确认的段都被确认后，才允许发送小数据段)
    • The receiving window is at least half open(接收窗口至少打开了一半，保证有足够空间接收大数据段)
    • The Nagle algorithm is disabled(或直接禁用 Nagle 算法，适用于对延迟敏感的场景)
    • 接收方The receiver avoids SWS by not sending an updated window size unless buffer 有 enough 空间
    • the update will open the window by at least 50% of its maximum buffer size(窗口更新后至少能打开最大缓冲区的 50%)
    • sufficient to accommodate one maximum-sized segment.(或窗口更新后足够容纳一个最大尺寸段)

  • TCP Congestion Control

  • 目标

    • Maximize throughput：最大化网络吞吐量
    • Adapt to dynamic network load：动态适应网络负载变化（如时段、新应用接入等）
    • 基于 Bandwidth Delay Product（带宽时延积）调整发送窗口，平衡带宽与 RTT（往返时间）

  • 如何判定阶段？

    • ssthresh
    • RTT 估计与 RTO 设置 (Retransmission Timer)
    • 问题：RTO (Retransmission Time-Out) 设得太短会误传，太长会浪费时间。（If the value is too short, the connection will retransmit prematurely, even though the original segment has not been lost；If the value is too large, the connection will remain idle for a long period of time after a lost segment）
    • Smoothed RTT (SRTT)：由于 RTT 动态变化，TCP 使用加权移动平均来平滑估算：
      • $下一个SRTT = (\alpha \times 当前SRTT) + ([1 - \alpha] \times 上一个RTT)$
    • Jacobson 算法：为了更科学地设置 RTO，引入了 Mean Deviation (MDEV)，即 RTT 的偏差：
      • Early versions of TCP used: RTO = β * SRTT– (β is a fixed variance typically = 2)
      • Jacobson proposal using Mean Deviation (MDEV):
      • MDEV = $\alpha \times MDEV + (1 - \alpha) |SRTT – RTT|$
      • $RTO = SRTT + 4 \times MDEV$
      • 网络稳定（MDEV 小）→ 安全边际小，RTO 更贴近 SRTT; 网络抖动大（MDEV 大）→ 安全边际大，避免过早重传, 比固定倍数 β 更自适应、更科学
    • Karn’s Algorithm：在计算 RTT 时，忽略重传段ignore retransmitted segments，因为无法确定 ACK 是对应原始包还是重传包– removes ambiguities。

  • 四个特点-阶段

    • slow start (慢启动/指数增长)

      触发条件：连接初始化时，或发生拥塞后 cwnd 重置为 1 时

      核心逻辑：

    • 初始状态：cwnd = 1，ssthresh = 2¹⁶ - 1

    • 每收到一个 ACK：cwnd = cwnd + 1（等价于指数级增长，因为每个 ACK 都会让窗口翻倍）

    • 阶段结束：当 cwnd ≥ ssthresh 时，切换到 Congestion Avoidance 阶段

    • congestion avoidance-Additive Increase(加性增/线性增长)

      触发条件：cwnd > ssthresh 时

      核心逻辑：

    • 线性增长：每收到一个窗口内所有段的 ACK 后，cwnd = cwnd + 1（避免指数增长导致网络过载）

    • 目标：缓慢探测可用带宽，防止突然拥塞

    • multiplicative decrease**(严重拥塞-乘性减)**

      触发条件：检测到拥塞（如超时、重复 ACK）时

      核心逻辑：

    • ssthresh = timeout / 2（将慢启动阈值减半）

    • cwnd = 1（重置拥塞窗口，重新从慢启动开始）

    • fast retransmit**(轻度拥塞-快速重传)**

      触发条件：收到3 个及以上重复 ACK（duplicate ACKs）时，推断某段丢失

      核心逻辑：

    1. Fast Retransmit（快速重传）：Retransmit segment immediately after receiving duplicate ACKs (usually 3) instead of waiting for a timeout无需等待超时，直接重传丢失的段，避免长时间等待导致吞吐量下降

    2. Fast Recovery（快速恢复）(TCP Reno)：

      • ssthresh = 3-ACKs / 2（执行乘性减）
      • cwnd = ssthresh，直接进入拥塞避免阶段（线性增长），不进入慢启动
      • 作用：保持通信管道（”pipe”）不为空，避免吞吐量骤降，更快恢复到可用带宽

      与 TCP Tahoe 的区别：

    • Tahoe：检测到丢包（无论超时或重复 ACK），均重置cwnd=1，进入慢启动
    • Reno：仅超时丢包才进入慢启动；重复 ACK 丢包则走 Fast Retransmit + Fast Recovery，维持更高吞吐量

  • Summary of TCP Operation

  • Employs sliding window to improve performance.

  • Sets up connection before any data exchange.

  • Clears down connection after finishing communication.

  • Segment header contains source port, destination port, sequence number, ACK number = next sequence number expected to be received, space for actual data and flags.

  • Most important flags are SYN, ACK and FIN (SYN used in connection set-up and FIN terminates opened connection)

  • User Datagram protocol (UDP)

  • UDP is a connectionless, unreliable, best effort, and only provide process-to-process communication.

  1. Core Characteristics (核心特性)：Not guaranteed delivery→No preservation of sequence+No protection against duplication
    • Connectionless ,Unreliable , unordered datagram service数据报而非字节流
    • No error correction capability, No flow control, No congestion control
    • Error detection include payload（checksum），无法重传
  2. Strategic Advantages & Usage (应用场景)
    • Only suitable for services where error checking and correction is either not necessary in the application, and time-sensitive which require less interaction between sender and receiver
    • No acknowledgement needed; faster than TCP，Less overhead
    • Ideal for Real-time Data: Online Gaming，Streaming/VoIP (Skype.）
